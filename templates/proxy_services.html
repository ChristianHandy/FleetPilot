Safety model

Only administrators can change routes. FleetPilot validates names, paths, hosts and ports; the root-owned helper renders and reloads HAProxy.

What this setting does: HAProxy on the Raspberry Pi listens at http://192.168.1.100/. FleetPilot stays on the root path /. A route such as /immich sends only requests beginning with /immich to the backend you select. The backend receives that original path, so it must support running below /immich. Do not use FleetPilot's root path or reserved paths.

Add a service in four safe steps

1. Choose a unique public path

Use a short path such as /immich, /paperless or /grafana. Users will open http://192.168.1.100/your-path.

2. Enter the internal destination

Enter the server's LAN address and the port the application already listens on. Example: an app at 192.168.1.52:3000.

3. Select a health path

Use / if a normal page returns HTTP 200, or the application's own health endpoint such as /healthz.

4. FleetPilot applies safely

The route is validated, HAProxy is tested and reloaded. If validation or reload fails, FleetPilot restores the previous working routes.

Example: public path /paperless + backend 192.168.1.56 + port 8000 means users browse http://192.168.1.100/paperless. If Paperless only works at /, configure its own reverse-proxy base path first; FleetPilot intentionally does not rewrite application paths.

Proxmox console routes

Proxmox cannot safely run under a path such as /pve01, because its interface requests root-relative resources and console WebSockets. FleetPilot therefore assigns each Proxmox host a dedicated TLS passthrough port. Proxmox retains its own login and certificate.
